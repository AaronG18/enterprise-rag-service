## The single OPEN item

**R-03 monetary cost.** Token usage is measured/estimated and the arithmetic is implemented
(`configs/pricing.json` + `src/ragserve/evaluation/cost.py`), but no price list was available for
the model versions used, so the repository prints "no price is configured" instead of a fabricated
USD figure. Closing it requires the operator to fill `configs/pricing.json` with real prices; the
report then produces the per-1,000-call figure automatically.

## What this QA deliberately does not claim

* Deterministic quality numbers are a **pipeline floor** (answers are assembled from retrieved
  sentences), not evidence about a model's generation quality.
* Model-backed numbers come from 30 cases per configuration; single-run differences of a few
  points are treated as noise (demonstrated: flash+hybrid+rerank measured 0.7174 / 0.6159 /
  0.8188 across three runs).
* Latency figures come from a 53-chunk in-memory index on a developer machine. The 10 s bound is
  met with margin, but these are not production SLA numbers.
* Token counts from the local CLI endpoint are `estimate` (the endpoint returns no usage).
