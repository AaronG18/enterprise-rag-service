# PROJECT.md

Shared, version-controlled facts about this repository. Anything here is meant to be read
by humans *and* agents, and it changes rarely. Anything personal, volatile or taste-based
belongs elsewhere.

> Rule of thumb for contributors: **if it is a fact about this project, it goes here.
> If it only applies to one person's setup, it does not.**

## Purpose

`enterprise-rag-service` is a bilingual (CN/EN) Retrieval-Augmented Generation QA service
over an internal-style knowledge base, built so that every architectural claim can be
re-derived by running a command. It is simultaneously:

1. a **service** - retrieval modes, reranking, refusal, PII redaction, caching, tracing;
2. an **evaluation harness** - reproducible scoring for retrieval and generative quality;
3. an **agent harness** - `harness/RULES.md`, `harness/ROLES.md`, `harness/skills/`
   define how an AI agent is allowed to change this repo.

## Commands (these must always work)

| Command | Purpose | Environment requirements |
|---|---|---|
| `python scripts/run_tests.py` | hermetic test suite (unit + golden) | none. No network, no credentials, no third-party packages. |
| `python scripts/run_eval.py --all` | retrieval comparison + generative scoring + ops report | none, in the default `deterministic` provider mode |
| `python scripts/run_eval.py --all --provider openai` | same evaluation against a real model | `OPENAI_API_KEY` / compatible endpoint configured in `configs/` |

Python **3.11+**. If a command above needs `pip install`, that is a regression - open an issue.

## Design invariants

| ID | Invariant | Why it exists |
|---|---|---|
| INV-1 | Third-party dependencies: **zero** on the critical path | A fresh clone must reproduce our numbers, forever, without a working package index. Real providers are adapters, never requirements. |
| INV-2 | Every provider (embedding, rerank, LLM, judge) is swappable by config | "Swap the model version" must be a config diff, otherwise the evolvability requirement is unmet. |
| INV-3 | Metrics carry a provenance tag | Distinguishes a reproducible measurement from a plausible number. See `harness/RULES.md` R3. |
| INV-4 | Answers are grounded in retrieved context or refused | This is the core correctness claim of the service; it is tested, not asserted. |
| INV-5 | Corpus is synthetic and deterministic | Keeps the repo publishable and makes cross-commit comparisons valid. |

## Directory contract

| Path | Contents | Hand-edited? |
|---|---|---|
| `src/` | service modules | yes |
| `configs/` | retrieval modes, model versions, thresholds | yes |

| `harness/` | RULES, ROLES, skills | yes |

## Metrics vocabulary

Definitions live in `docs/metrics/`. Short version, so contributors argue about the same thing:

* **Faithfulness** - fraction of answer claims supported by the cited context.
* **Context Precision** - fraction of retrieved chunks that actually contributed to the answer.
* **Answer Compliance** - answer obeys the output contract (citations present, bounded length, language matches question, no unsupported extrapolation).
* **Refusal Appropriateness** - refusal happens exactly when it should (low confidence, out-of-scope, safety hit) and includes actionable guidance.
* **Style Consistency** - answers conform to a fixed style rubric (tone, structure, citation format), independent of which question was asked.
